# Guides — repeatable "how to do X" recipes

Short, concrete how-tos for the **recurring** tasks in this project — the things you'll do over and
over (add a feature of type Y, wire a new screen, add a data row). They turn the "Common tasks"
bullet in `CLAUDE.md` into step-by-step recipes so neither you nor Claude has to re-derive the
pattern each time.

## Convention
- One file per recipe: `adding-a-<thing>.md` (or `how-to-<verb>.md`).
- Keep it a **recipe**, not prose: numbered steps, the exact files/types to touch, and a final
  "verify it worked" check. Link to the real example in the codebase.
- Write a guide the *second* time you do something — once a task has a repeatable shape, capture it.
- These describe *how*; `docs/DESIGN.md` is *what/why* and `docs/adr/` is *why-we-chose*.
